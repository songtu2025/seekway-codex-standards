# SEEKWAY Codex 开发任务模板

使用者只需填写第 1 部分；不知道的内容可以写“不清楚”。Codex 须先追问不明确的要求，再按任务级别补全适用内容；非简单任务实施前须获得确认。

## 1. 使用者描述

### 业务背景和当前做法

说明为什么要改，以及现在用什么工具、按什么步骤处理。

### 想解决的问题

说明哪里浪费时间、容易出错或无法完成。

### 期望结果

说明完成后希望看到的变化。

### 怎样算做成了

用业务语言描述可以接受的结果；不清楚时由 Codex 协助整理。

## 2. Codex 需求转换

- 任务级别：简单 / 标准 / 高风险，由 Codex 判定并说明理由。
- 现状流程 `As-Is`：由 Codex 整理。
- 必须保留的业务规则和硬约束：由 Codex 整理并确认。
- 现有工具限制、补救动作和可调整习惯：由 Codex 整理。
- 适合目标系统的流程 `To-Be`：由 Codex 提出并由用户确认。
- 目标、范围、不做事项和验收标准：由 Codex 整理并确认。

## 3. Codex 设计与计划

- 适用的设计视角：角色与职责；业务规则及异常；用户操作与反馈；数据来源、去向和生命周期；页面与状态；前后端、接口、集成和失败边界。按 `docs/codex/workflow.md` 第 4.4 节填写结果，不适用的视角说明理由。
- 横向约束：按需说明安全、隐私、权限、审计、性能、可用性、容量和兼容性。
- 界面设计（命中时）：按 `docs/codex/interface-design.md` 在本说明中记录执行范围、意图解释和复用依据；需要探索时补充空间版本、覆盖结果、候选编号、筛选理由、方向确认和原型反馈。
- 验证策略：前端 Demo / 技术验证 / 直接实现，由 Codex 按最大不确定性建议。
- 允许修改范围：由 Codex 列出。
- 禁止修改范围：无 / 待确认。
- 数据库、认证、权限、配置、依赖和部署影响：填写受影响项及结论；无影响时写“无”。
- 新增生产依赖：新 Web 项目默认使用 `antd@6` 和 `@ant-design/icons@6`；需要图表时默认使用官方 `echarts` 包。现有项目变更选型或增加其他生产依赖须单独确认。
- 风险、回滚和验证方案：由 Codex 说明。

## 4. 效果复查（有可观测业务效果时填写）

- 改造前基线、目标和指标：待填写。
- 指标数据来源：待填写。
- 复查负责人和时间：待填写。
- 达标、未达标或出现副作用时的动作：保留 / 优化 / 回滚 / 暂停 / 下线 / 待确认。

没有持续业务效果的任务注明“不适用”，按验收标准完成最小闭环。

配置中不得填写真实生产凭据。Codex 按 `AGENTS.md` 及任务命中的专项规范执行。
