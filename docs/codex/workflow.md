# Codex 开发流程与项目边界

当任务涉及代码、项目结构、配置、依赖、部署、项目文档或生产边界时，必须读取本文件。本文是根目录 `AGENTS.md` 的专项扩展；两者冲突时必须停止并修正规则，不得自行选择其一。

## 1. 技术与环境基线

以下是新项目默认基线；历史项目以已经确认的实际技术栈和运行环境为准，并在 README 或根目录 `AGENTS.md` 中记录差异：

- 开发环境：Windows
- 代码托管：GitHub
- 生产环境：阿里云 ECS
- 前端：React、TypeScript、Vite
- 后端：Python、FastAPI、Pydantic、SQLAlchemy、Alembic、pytest、Ruff，以及项目选择的 Mypy 或 Pyright
- 部署：Docker、Docker Compose、Nginx

未经明确批准，不得更换项目已经采用的前端或后端框架、数据库访问或迁移方案、部署方式，不得引入新的基础设施组件或生产依赖。

## 2. 标准项目结构

新项目默认采用前后端分离、同一仓库管理的结构：

```text
project-name/
├── AGENTS.md
├── README.md
├── .env.example
├── .gitignore
├── compose.yaml
├── docs/
│   └── codex/
├── frontend/
│   ├── package.json
│   ├── src/
│   └── tests/
├── backend/
│   ├── pyproject.toml
│   ├── alembic.ini
│   ├── app/
│   ├── migrations/
│   └── tests/
├── deploy/
└── .github/
    ├── workflows/
    ├── ISSUE_TEMPLATE/
    ├── pull_request_template.md
    └── CODEOWNERS
```

新项目必须遵守：

1. 前端代码放在 `frontend`，后端代码放在 `backend`，项目文档放在 `docs`。
2. 数据库迁移放在 `backend/migrations`，部署配置放在 `deploy` 或根目录明确位置，GitHub 配置放在 `.github`。
3. 未经批准不得改变一级目录结构；项目不需要的二级目录可以省略。
4. 不得提交临时文件、日志、数据库文件和真实业务数据。

历史项目不受上述目录命名约束，必须优先保持现有结构和兼容性；不得仅为符合模板进行无业务收益的全量重构。

## 3. 开始开发前

修改代码前必须：

1. 阅读根目录和相关子目录中的 `AGENTS.md`，并按其中索引加载与任务有关的专项规范。
2. 阅读 README、需求文档、相关代码和测试。
3. 检查相关调用链、现有实现方式和可复用能力。
4. 复述需求、验收标准和明确不做的事项。
5. 列出计划修改的文件及修改内容。
6. 说明是否涉及数据库、认证、权限、配置、依赖或部署。
7. 识别风险和回滚方式，给出测试与验证方案。
8. 非简单任务在获得用户确认前不得开始修改。

涉及 Web 界面时，还必须读取 `docs/codex/frontend.md` 和项目的 `docs/web-ui-standard.md`；后者不存在时读取 `templates/web-ui-standard-template.md` 并报告缺失。随后检查已有设计令牌、组件库、页面布局和相似页面，并明确设计来源、目标视口及各页面状态。

## 4. 修改范围

必须：

1. 只修改完成当前任务所必需的文件，保持现有业务规则、接口和兼容性。
2. 优先复用已有代码和实现模式，新增或修改业务逻辑时补充必要测试。
3. 发现无关问题时只记录，不顺带修改。

不得：

1. 自行增加功能、页面、接口、业务规则或需求中没有的业务字段。
2. 进行与当前任务无关的重构或修改无关文件。
3. 擅自删除已有功能、接口、字段或数据。
4. 擅自修改公共模块、认证、权限或部署配置。
5. 为“以后可能使用”提前增加代码、字段或组件。
6. 在多个位置复制相同业务规则。

## 5. 安全与生产边界

不得主动读取、生成、提交、输出或传播：

- 真实密码、Token、AccessKey、SecretKey 和私钥。
- 生产环境变量的真实值。
- 未脱敏的真实业务数据。
- 包含真实敏感信息的数据库文件、日志、上传文件和导出结果。

可以读取和处理：

- 认证相关的代码、字段名和配置结构。
- 不包含真实凭据的 `.env.example` 和占位值。
- 测试数据、模拟数据和已经脱敏的数据。
- 用户明确提供且不包含真实敏感信息的需求附件、示例文件和设计资料。

允许使用不显示命中值的自动化工具扫描源码和提交记录。意外发现真实敏感信息时，应停止处理相关内容并提醒用户，不得在日志或回复中复述其值。不得直接修改生产数据库或自动执行生产迁移；生产操作只能由部署负责人执行。

## 6. 项目文档

创建或维护项目时，README 至少包含：

- 项目用途、适用范围和明确不做的事项。
- 技术栈、系统架构和关键业务规则。
- 本地启动、测试和构建方式。
- 部署文档入口。

根目录 `AGENTS.md` 至少包含业务边界、Codex 修改规则、禁止修改内容、专项规范索引、必须执行的检查以及数据和 Git 安全要求。重要业务规则不得只存在于聊天记录或个人记忆中。
